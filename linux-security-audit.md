# 🐧 Linux Security Audit: Чек-лист и точки контроля

![Linux](https://img.shields.io/badge/OS-Linux-blue.svg)
![Security](https://img.shields.io/badge/Topic-InfoSec-red.svg)
![Type](https://img.shields.io/badge/Type-Hardening%20Checklist-green.svg)

Шпаргалка для аудита конфигурации Linux-серверов (Hardening). Помогает быстро найти слабые места в системе, проверить соответствие политикам ИБ и подготовить сервер к эксплуатации.

> 💡 **Как пользоваться:** Большинство команд требуют прав `root` или `sudo`. Блоки кода можно копировать прямо в терминал.

---

## 👤 1. Учётные записи и доступ (Accounts)

Проверяем, кто вообще может зайти на сервер и как.

| Что проверяем | Где смотреть / Команда | Почему это важно (ИБ) |
| :--- | :--- | :--- |
| **Все пользователи** | `cat /etc/passwd` | Базовая инвентаризация. Поиск забытых или лишних УЗ. |
| **Общие учетки** | `grep -E '^(admin\|user\|test):' /etc/passwd` | Общие логины (`admin`, `test`) запрещены, т.к. нельзя отследить, кто именно действовал. |
| **Дубликаты UID** | `awk -F: '{print $3}' /etc/passwd \| sort \| uniq -d` | Признак некорректного управления. Каждый пользователь должен иметь уникальный UID. |
| **Сервисные УЗ** | `awk -F: '($3 < 1000 && $7 !~ /(nologin\|false)/) {print $1}' /etc/passwd` | Сервисные учетки не должны иметь интерактивного shell (чтобы под ними нельзя было зайти). |
| **Вход под root** | `last root \| head -10` | Прямой вход под `root` по SSH — грубое нарушение. Все админ-действия — через `sudo`. |
| **Root по SSH** | `grep PermitRootLogin /etc/ssh/sshd_config`<br>`sshd -T \| grep permitrootlogin` | Должно быть `PermitRootLogin no`. Проверяем и файл, и реально примененный конфиг (`sshd -T`). |

## 🔑 2. Парольная политика (Password Policy)

Проверяем, насколько сложно подобрать пароль.

| Что проверяем | Где смотреть / Команда | Почему это важно (ИБ) |
| :--- | :--- | :--- |
| **Сложность паролей** | `cat /etc/security/pwquality.conf`<br>`grep pam_pwquality /etc/pam.d/common-password` | Параметры `minlen`, `minclass` защищают от брутфорса. Модуль PAM должен быть подключен. |
| **Пустые пароли** | `awk -F: '($2 == "") {print $1}' /etc/shadow` | Критическая уязвимость. Такие УЗ можно использовать без пароля. |
| **Алгоритм хеша** | `awk -F: '($2 ~ /^\$6\$/) {print $1}' /etc/shadow` | Должен быть **SHA-512** (`$6$`). MD5 и DES устарели и легко взламываются. |
| **Срок действия** | `grep PASS_MAX_DAYS /etc/login.defs`<br>`chage -l <user>` | Пароли должны истекать (например, через 90 дней). `chage` показывает реальные сроки для юзера. |
| **История паролей** | `grep -r remember /etc/pam.d/` | Запрет повторного использования старых паролей (например, `remember=5`). |
| **Открытые пароли** | `grep -rInE '(password\|secret)\s*=' /etc /opt /srv` | Поиск паролей в открытом виде в конфигах. Критическая утечка. |
| **Sudo права** | `cat /etc/sudoers /etc/sudoers.d/*` | Ищем `NOPASSWD` (ввод пароля для sudo отключен) и избыточные привилегии. |

## 📝 3. Логирование и Аудит (Logging)

Проверяем, останутся ли следы, если что-то случится.

| Что проверяем | Где смотреть / Команда | Почему это важно (ИБ) |
| :--- | :--- | :--- |
| **Статус rsyslog** | `systemctl status rsyslog` | Если демон не работает, события нигде не сохраняются (слепая зона). |
| **Ключевые логи** | `ls -la /var/log/auth.log /var/log/secure` | Существуют ли файлы и наполняются ли они. |
| **Права на логи** | `ls -la /var/log/auth.log` | Должно быть `640 root:adm`. Иначе любой юзер прочтет логи. |
| **События SSH/sudo** | `grep -i sshd /var/log/auth.log \| tail -5` | Подтверждение, что действия админов и попытки входа фиксируются. |
| **Логи sudo** | `grep -E 'Defaults.*log' /etc/sudoers` | Настройка отдельного лога для `sudo` (все введенные команды). |
| **Централизация** | `grep -rE '^\\*\\.\\*.*@' /etc/rsyslog.*` | Настройка отправки логов на SIEM. Если сервер скомпрометируют, локальные логи удалят. |

## 🌐 4. Сеть и Файрвол (Network & Firewall)

Закрываем лишние двери в систему.

| Что проверяем | Где смотреть / Команда | Почему это важно (ИБ) |
| :--- | :--- | :--- |
| **Слушающие порты** | `ss -tulnp` | Базовая инвентаризация. Ищем лишние сервисы и неизвестные процессы. |
| **Правила файрвола** | `ufw status verbose`<br>`iptables -L -n` | Что реально разрешено извне. |
| **Политики по умолчанию**| `iptables -S \| grep -E '^-P'` | Должно быть `DROP` (deny by default). Разрешено только то, что явно открыто. |
| **NAT-правила** | `iptables -t nat -L -n` | Проверка на несанкционированный маскарадинг или проброс портов. |

## ⚙️ 5. Сервисы и Изоляция (Services)

Проверяем актуальность ПО и права процессов.

| Что проверяем | Где смотреть / Команда | Почему это важно (ИБ) |
| :--- | :--- | :--- |
| **Версии ОС/Ядра** | `cat /etc/os-release`<br>`uname -a` | Проверка на End-of-Life (EOL). Устаревшие ОС не получают патчи. |
| **Обновления** | `apt list --upgradable`<br>`dnf check-update` | Ищем security-обновления. Они должны ставиться в первую очередь. |
| **World-writable** | `find / -xdev -type f -perm -0002` | Файлы, которые может изменить любой пользователь (риск подмены). |
| **Защита сети (sysctl)**| `sysctl net.ipv4.tcp_syncookies ...` | Защита от SYN-flood, подмены маршрутизации (source routing) и т.д. |
| **Пользователи процессов**| `ps -eo user,comm`<br>`systemctl show -p User` | Принцип наименьших привилегий. Сервисы (Nginx, Samba) должны работать от своих УЗ, а не от `root`. |

---

## 🕸️ 6. Веб-сервисы и DNS (Web & DNS)

Специфические проверки для сетевых сервисов.

| Что проверяем | Где смотреть / Команда | Почему это важно (ИБ) |
| :--- | :--- | :--- |
| **Скрытие версии** | `grep server_tokens /etc/nginx/nginx.conf` | Должно быть `off`. Чтобы хакер не знал точную версию Nginx и не искал под нее эксплойты. |
| **Заголовки Nginx** | `grep add_header /etc/nginx/nginx.conf` | Наличие Security Headers (HSTS, X-Frame-Options) для защиты от XSS и Clickjacking. |
| **SSL/TLS** | `grep -E 'ssl_protocols\|ssl_ciphers' ...` | Должны быть только TLSv1.2 и 1.3 со стойкими шифрами. |
| **DNS Рекурсия** | `grep recursion /etc/named.conf` | Должно быть `no` (если сервер не является публичным резолвером). Иначе сервер используют для DNS Amplification DDoS-атак. |
| **DNS клиенты** | `grep allow-query /etc/named.conf` | Ограничение, кому DNS-сервер вообще отвечает. |

## 📁 7. Файловый сервер и Именование

| Что проверяем | Где смотреть / Команда | Почему это важно (ИБ) |
| :--- | :--- | :--- |
| **Права на шары** | `ls -la /srv/files`<br>`stat -c '%U:%G %a' /srv/files` | Папки не должны быть доступны на запись всем (777). Доступ только для нужных групп (`root:fs_admins 750`). |
| **Имя хоста** | `hostname` | Не должно превышать 15 символов (ограничение NetBIOS). Должно соответствовать корпоративному стандарту именования. |

---
*Данный чек-лист покрывает базовый уровень (Baseline) защиты Linux-системы. Для полного аудита рекомендуется использовать специализированные сканеры уязвимостей и SCAP-профили (например, CIS Benchmarks).*
